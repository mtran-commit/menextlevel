CUSTOMER FLOW

When a customer clicks:

ORDER NOW

Send the selected product ID and quantity to the server.
Server retrieves the current product information from our database.
Server creates a Stripe Checkout Session.
Redirect customer to Stripe Checkout.
Stripe collects payment and shipping information.
After successful payment, redirect customer to:

/shop/order-success

If they cancel payment, return them to:

/shop

IMPORTANT SECURITY RULE

Never accept the price sent from the browser as authoritative.

The browser should send:

product ID
quantity

The server must read the real price from our product database before creating the Stripe Checkout Session.

This prevents customers from manipulating prices.

STRIPE WEBHOOK — CRITICAL

Do NOT mark an order as paid just because the customer reaches the success page.

Use a Stripe webhook.

Handle:

checkout.session.completed

When Stripe confirms successful Checkout:

find the order using Stripe metadata/session ID
set payment status to PAID
set order status to NEW
save Stripe PaymentIntent/reference
save customer name/email
save shipping address
save amount paid
record payment timestamp

Stripe recommends using webhooks such as checkout.session.completed to fulfil orders after Checkout.

Webhook processing must be idempotent so receiving the same Stripe event twice cannot create duplicate orders or duplicate fulfilment.
